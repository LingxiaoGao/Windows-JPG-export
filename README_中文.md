# 照片高清导出器 v3.0.1 · Windows 10/11 x64 便携版

解压整个 ZIP，打开 `WindowsJPGExporter` 文件夹，双击 `WindowsJPGExporter.exe`。保留旁边的 `_internal` 文件夹；无需安装 Python、Pillow 或 ExifTool。照片处理离线完成，不上传照片、不采集遥测、无需管理员权限。

## 日常操作

1. 选择输入照片文件夹，或将文件夹拖入输入框。默认递归处理 ARW、JPG、JPEG，大小写不敏感。
2. 选择输入目录之外的输出根目录。输入与输出不能相同或互为上下级。
3. 选择预设，点击“快速预检”，查看文件数量和可能异常。
4. 点击“开始导出”。可以暂停、继续、安全取消；完成后打开输出文件夹。
5. 下次使用同样设置，软件会核验已完成输出的 SHA-256，再断点续跑。

窗口会适应屏幕与 DPI。较小窗口可用右侧滚动条或鼠标滚轮访问完整界面；横向内容不足时也有滚动条，进度和取消等按钮不会丢失。

默认全部处理。仅 RAW / 仅 JPG 可以在输入区域选择。同名 RAW/JPG 都处理，不自动忽略 RAW。

## 三个预设

| 预设 | 分辨率与质量 | 元数据与颜色 |
|---|---|---|
| 原始 JPEG | ARW 提取最高像素面积的有效内嵌 JPEG；JPG 直接复制；全部字节保持一致 | 原有 ICC/EXIF 保留，可能含 GPS；不保证像素已转正 |
| 微信朋友圈 | 长边最高 2560px；起始质量 95；超限时逐级降至最低 88 | sRGB，像素转正，Orientation=1；保留拍摄信息，删除定位相关块 |
| 高质量分享 | 长边最高 4096px，质量 95；默认不限制文件大小 | 同朋友圈的方向、颜色和隐私规则 |

小图默认保留原尺寸并正常完成，不放大、不裁切、不拉伸，清单中标记 `resolution_below_target`。朋友圈的 2560px 是导出预设，不保证微信客户端最终展示尺寸。

默认正常大小上限是 **4,000,000 字节（十进制 4MB）**，不是目标大小。小于上限的图片直接接受，不补数据、不人为增大。最低质量 88 仍超过上限时，保留分辨率与最低质量，标记 `size_over_limit`；完成界面显示数量。

已有 JPG 如果不用缩放、旋转、色彩转换、锐化，且清理元数据后满足大小设置，则保留压缩图像数据，仅重建元数据，不再有损压缩。输入 JPEG 的原编码质量不能可靠推断，清单会说明“保留输入编码”，不会把它谎称为本次质量 95。

## 输出和文件名

三个预设分别输出到 `JPEG_Original`、`JPEG_WeChat_2560`、`JPEG_Share_4096`。默认保留目录结构；自定义长边仍使用所选预设的固定目录名，以清单的实际输出尺寸为准。

同目录同名 ARW/JPG 变为 `DSC01234_ARW.jpg` / `DSC01234_JPG.jpg`。若还与其他现有基本文件名冲突，或取消目录层级导致重名，附加稳定的相对路径哈希。不会无限添加 `_1`、`_2`，不同子目录不会误合并。

每个预设目录包括 `manifest.csv`、`progress.sqlite3`、`errors.log`、`summary.csv`。清单是带 BOM 的 UTF-8，可用 Excel 打开。区分 `byte_identical`、`metadata_only`、`reencoded`，记录实际编码质量、方向、色彩、低分辨率和超限情况。

旧 `jobs` 数据表保留，新记录使用 `exports` 表。不同预设使用独立日志；参数变化自动重新处理。若选择“跳过已有文件”，只表示遵从你的选择，并不表示核验了旧文件正确性。默认推荐“验证后断点续跑”。

## 方向、颜色、隐私

方向使用 JPEG 自身 EXIF 或 ARW 容器方向，支持 1–8 全部值和镜像。缺少方向时假定像素已正向并记日志；冲突或歧义明确报错。高级“方向来源”仅在目视检查具体异常照片后调整，避免混合照片强制重复旋转。

有效 ICC 使用 LittleCMS 转换至 sRGB；已确认 sRGB 的 ICC 可保留颜色像素。明确 Adobe RGB 标记但缺少 ICC 时，使用程序生成的 A98 RGB 兼容矩阵配置进行实际转换；不是直接改标签。完全缺少颜色依据时，按任务要求假定 sRGB并记录。损坏 ICC 会报告错误。

分享模式先清除原元数据块，再仅复制拍摄 EXIF 白名单：时间、相机、镜头、焦距、光圈、快门、ISO、曝光参数等；写入 Orientation=1 与 sRGB ICC。GPS、XMP、IPTC、注释和 MakerNotes 不复制，避免留下地理位置。取消“保留拍摄 EXIF”时仍保留正确方向和色彩信息。

原样模式保留 JPEG 的所有字节，可能含 GPS；它不保证自动转正或删除定位。需要隐私清理时使用分享模式。

## 预检和稳定性

快速预检只检查 JPEG 头、尺寸和元数据，不完整解码所有像素。显示的“初步正常”不等于通过完整解码；损坏的压缩数据可能到导出时才发现。大小超限数是估计，实际统计以完成报告为准。可勾选“先处理预检正常照片”。ARW 预检仍需读取内嵌 JPEG 数据，并非零开销。

默认单个后台工作线程，适合外置 HDD；逐张释放图像对象。原图严格只读，完整临时 JPEG 验证后原子替换正式输出。文件占用有限重试；空间不足、硬盘断连、损坏文件会记录错误。安全取消在处理点执行，工具单次调用最多等待 120 秒；已完成结果保留。

保留原样 JPEG 可能小于相机 RAW 的像素数。ARW 无有效 JPEG 时明确失败，始终禁止 RAW 解码回退。超出 Pillow 安全像素限制的异常大图会失败，不强制关闭内存保护。

输出目录保留历史文件。改变设置或某次失败后旧图片可能仍在，必须结合最新清单识别有效结果。建议不同照片库使用独立输出根目录。
